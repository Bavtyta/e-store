# Миграция контракта списка товаров на 1.3

`ProductListItem` 1.3 добавляет обязательные поля выбора варианта и явной семантики
цены. Из-за `strictObject` это несовместимое изменение для старого и нового клиента.

Безопасная последовательность выкладки:

1. Backend начинает распознавать `X-Storefront-Contract-Version: 1.3` и возвращает
   новый DTO только при этом заголовке. Запросы без заголовка временно получают DTO 1.2.
2. Contract-тесты backend проверяют обе формы ответа и cross-field правила
   `purchaseAction`, `priceType`, упаковки и выбора вариантов.
3. Выкладывается frontend 1.3, который всегда отправляет заголовок для списка товаров.
4. После исчезновения клиентов 1.2 прежняя форма ответа удаляется отдельным изменением.

Переключать форму ответа глобально до шага 3 нельзя: старый frontend отвергает новые
поля, а новый frontend намеренно отвергает неполный DTO 1.2.
